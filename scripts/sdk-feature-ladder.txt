# sdk-feature-ladder.txt — authoritative feature-release ladder for the
# multi-SDK version-skew attribution in scripts/sdk-matrix.sh (the addedIn
# classification: a dartq-only one-sided entry whose code family belongs to a
# feature that is enabled by default only ABOVE the oracle's language minor
# can never be emitted by that oracle — it is version skew, not a defect
# candidate; mirrors how the removedIn code families are excluded).
#
# Rung = the language minor at which the feature is enabled BY DEFAULT (the
# `enabledIn` / experimentEnabledVersion field). `experimentalReleaseVersion`
# (flag-enabled-by-hand) is noted in the rung's comment but never used as the
# rung: the sweep passes no --enable-experiment flags, so a flag-available
# but default-off oracle (e.g. dot-shorthands at 3.9, primary constructors at
# 3.12) still cannot emit the feature's diagnostics.
#
# Upstream verification (2026-10-13): every rung cross-checked against TWO
# tables in the upstream Dart SDK source, which agree on all minors:
#   1. tools/experimental_features.yaml (enabledIn / experimentalReleaseVersion)
#   2. pkg/_fe_analyzer_shared/lib/src/experiments/flags.dart
#      (experimentEnabledVersion / experimentReleasedVersion)
# The sweep floor is Dart 3.0.7 (scripts/sdk-versions.txt), so the 3.0 rungs
# are inert for today's ladder — recorded for attribution generality if the
# floor ever drops below 3.0.
#
# Format: one `<minor>|<feature>|<code-name list>` row per rung, ascending
# by minor; `#` comment lines and blank lines allowed. Multiple rows may
# share a minor. <minor> is the BARE language-minor integer (0 = Dart 3.0,
# 13 = Dart 3.13) — the same integer the script derives from the oracle
# version banner ("3.0.7" -> 0) for the rung-above-oracle comparison. <minor> is the BARE language-minor integer (0 = Dart 3.0,
# 13 = Dart 3.13) — the same integer the script derives from the oracle
# version banner ("3.0.7" -> 0) for the rung-above-oracle comparison. The third field is a COMMA-separated list of diagnostic
# code names (or code-name prefixes) — the script joins them with `|` into
# the per-rung ERE — because the row separator itself is `|`. It is matched
# case-insensitively (codes are ascii_downcase'd first) against dartq-only
# one-sided (code,file) entry codes from raw-outputs.json. `-` = the rung
# has no syntax-plane code family in the gate universe (its faces are
# semantic-plane or oracle-side; see scripts/sdk-matrix-expectations.tsv).
# Keep code names lowercase and free of `"` and `\` (the script embeds the
# joined ERE in a JSON string). Bias the family membership CONSERVATIVELY: a
# code wrongly added here is excluded from defect candidates forever (a
# masked defect); a code wrongly omitted just stays a candidate until
# triaged.
#
# The language-version diagnostic family (invalid_language_version_override,
# illegal_language_version_override, inconsistent_language_version_override,
# language_version_too_high_explicit) is version skew by corpus pin, not by
# a feature rung — it stays in sdk-matrix.sh's SKEW_RE (removedIn structure).
